# Design proposal / ADR-0007 & ADR-0008 (PROPOSED, NOT APPROVED)

The minimal design isolates the six-ball historical analysis in this new repository. It rejects invalid/duplicate draws; explicitly excludes and counts pre-2015-10-07 rows when loading a modern-format panel, retains each original draw identity, computes exact sum bins, 26-PB vectors, positional top ten among *observed* PBs plus all observed PB ties at the tenth position (additional positions labeled OUTLIER_TIE), and observational white-ball counts/sets/parity. When fewer than ten PBs have observations, retain only those observed: the full vector still includes zero counts, but zero-count PBs are not generation candidates and cannot be OUTLIER_TIE. No hot/cold selection or claims of predictive edge.

Generator prototype accepts an explicit `Selection(peak,left,right)` and explicit nine-slot `(peak,left,right)` allocation summing to nine with each component positive. This is a caller-supplied *test parameter*, not an inferred or approved production rule. It selects only existing white sets associated with observed PBs in each requested bin; this is the conservative valid reconstruction strategy, not an assertion that the theory requires exclusively replaying historical sets. It fails when insufficient distinct observations exist. The tenth control is drawn independently and uniformly using `secrets.SystemRandom`. If it collides with an experimental ticket, fail the entire experimental cycle explicitly rather than redrawing using the experiment as a filter. Collision policy and uniqueness/independence priority remain open for operational generation. The control never uses frequency or PB rankings. Use timezone-aware generation/target timestamps; require `draw_date < target_date` and `ingested_at <= generated_at` where provenance is trustworthy (fail closed on missing/naive timestamps); an immutable row-level snapshot hash and cutoff are recorded. Historical backtests cannot claim earlier availability solely from a present-day DB: source ingestion times may be later than historical drawing times. No write to existing ledger.

Options requiring owner decision before operational generation: (A) qualify tail bins as nonempty; choose outermost lowest-frequency candidates with ties by sum, then Hamilton apportion nine slots with at least one per bin; (B) qualify by a minimum sample threshold and use a capacity-aware apportionment; (C) supply an exact manually approved bin/slot mapping each cycle. A/B are not adopted: frequency weighting can overwhelm tails, ties and sparse bins make the result highly unstable. Explicit C is supported for clean-room fixtures only. Owner approval must specify qualification, tie break, allocation, and shortage/replay policy before operational use.

Rollback: remove isolated source and fixtures in this repository; no reference change or production data migration. Production integration later requires independent review of source/storage contracts, isolated regression tests, human-approved release manifest, and verified rollback of adapter without deleting historical observations.

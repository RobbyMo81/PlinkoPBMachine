# Plinko theory specification — scoped implementation

The master total is `S = sum(5 distinct white balls) + PB`; valid modern-era range 16–361. Historical rows dated before 2015-10-07 are excluded and counted, not mixed with modern 69/26 format. For each exact sum S, frequency is count of original rows. For each S, counts for PB 1..26 sum to frequency(S); for each observed (S, PB), individual white counts 1..69 sum to 5 × frequency(S, PB). Preserve complete draw identities, dates, source hashes, sets, parity. PB ranking is frequency descending, PB ascending as tie order; positions 1..10 retained, plus any *observed* PBs tied at position 10, labeled OUTLIER_TIE. Zero-count PBs remain in 26-value vector, not ranking. Sparse bins retain fewer than ten PBs.

Current implementation: `plinko/analysis.py`, descriptive analysis and deterministic in-memory SVG histogram only; SQLite adapter opens mode=ro and excludes/reports pre-modern rows. Dataset SHA256 is calculated from canonical sorted validated rows (id, date, whites, PB, source, record hash); hash changes when any such field changes. It represents the input snapshot, NOT guaranteed public availability at historical generation time. The adapter makes no timestamp-leakage assertion and must not be used to backtest past generation times. No hot/cold selection, predictive inference, random control, experimental nine-ticket generator, tracking integration or production execution is implemented. Exact allocation, tail qualification, and collision treatment remain owner decisions (ADR-0007/0008). Lottery draws are random; historical frequencies do not increase per-ticket winning odds.
